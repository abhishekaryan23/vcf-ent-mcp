VCF Enterprise MCP / test lab

Northwind VCF Lab

This is the simulated lab the VCF Enterprise MCP is tested against: a fictional group, Northwind, with five workload domains on mixed VCF versions and one shared NSX. Every appliance is simulated; this is an unofficial project and is still under testing.

Use it from LM Studio

LM Studio's mcp.json now has two servers: vcf-northwind-oncall (read-only) and vcf-northwind-automation (changes need approval: python tools/org_sim/lab.py approve automation <plan_id>). Switch faults with lab.py switch; no need to edit LM Studio.

The estate

  • VCF 9.1.1 or shared component
  • Version differs from 9.1.1 (amber text in the diagram)
  • Physical or external

Fault scenarios you can switch to

Switch the lab with python tools/org_sim/lab.py switch <scenario>.

Estate faults

  • dfw_blocks_crm_sql A DFW rule blocks CRM web from its SQL tier.
  • bgp_down_fin BGP between t0-fin and the FTD pair is down.
  • fci_colocated_host_down A host carrying both Ledger FCI nodes goes down.
  • shared_nsx_cert_expired nsx-wld01 certificate expired; corp and dev both affected.
  • vpc_ip_exhausted ecom-private-app has no free IPs; eCommerce scale-out fails.
  • ad_fin_down fin.nwg.local domain controllers unavailable.
  • eu_web_quarantined RetailShop web VMs sit in the quarantine port group.
  • scm_oracle_reject_plus_noise A rule rejects Oracle (1521) clients, plus unrelated noise.
  • proxy_t1_detached t1-corp-dmz detached from the Tier-0; proxies lose internet.
  • healthy_noisy Nothing is broken; the estate just produces noise.

Orchestrator scenarios

  • orch_default Orchestrator 9.1.1 healthy; the Mail plug-in is older than 9.1.0.0401 (KB 447131).
  • orch_9_1_0 Orchestrator 9.1.0: the MCP warns about the known issues fixed in 9.1.1.
  • orch_role_conflict The service account has Workflow Designer and Viewer, so it is read-only (KB 438403).
  • orch_vc_unusable The vc-corp01 connection is unusable after a vCenter reboot (KB 452127).
  • orch_concurrent_edit A colleague edits "Disk usage report" between your dry run and your save.

Request flow

Every call is identified, filtered, schema-checked and policy-checked. Reads go straight to the appliances; writes are stopped at a human approver first.

  • Common steps (dark border)
  • Read path (blue border)
  • Write and approval path

The dashed line is the trust boundary: nothing past it is reached without the credential broker, the SSRF guard and TLS verification. Approval is run by a person with vcf-mcp plans approve <plan_id>, which signs an approval_id and a single-use nonce.
